## Glossary (fixed terms)

| Term | Meaning |
| --- | --- |
| **Set** | User-owned package of one type: Weapon, Armor, Mod, Pair, or Fashion |
| **Item** | Manifest reference (and roll or pin data when used) in a Set slot |
| **Armor piece** | One of: helmet, arms, chest, legs, class item |
| **Save** | Persist the Set to the library (create or update) |
| **Lifecycle** | Create, edit, fill slots, and delete a Set |

| **Attach** | Link a Set to a Build variant (live or snapshot) |
| **Synergy Type designation** | Intent label on a Set: `type` + optional `subType` (same shape as on a Build). Not a full library Synergy record. |
| **Armor set bonus** | Destiny armor collection bonus (2-piece and/or 4-piece) from the manifest `set-bonuses` data. |
| **Armor set bonus constraint** | Optional goal on an **Armor Set**: a bonus family plus a target tier (2-piece or 4-piece). |

Do not use kit, package, or experience as synonyms for **Set** in rules.

## 1. Definition

A **Set** is a user-owned package of gear or cosmetics.  
The system uses Sets as the normal composition path for a Build variant.  
A Set stores **manifest item references**, not full item copies.  
Set types: **Weapon**, **Armor**, **Mod**, **Pair**, **Fashion**.

A Set is a package, not a single filled slot.  
A Weapon Set or Armor Set needs **two or more items** to save or attach.  
A Mod Set needs mods on **two or more armor pieces** to save or attach.  
A Pair Set needs **both** an exotic weapon and an exotic armor to save or attach.  
An Armor Set is bound to one Destiny class.  
Weapon, Armor, Mod, and Pair Sets may designate **Synergy Types** (same model as Builds).

## 2. Why it exists

Players reuse the same gear groups across variants and builds.  
Sets let users attach packages and still override slots on a variant.  
Synergy Type designations mark play-pattern intent on the package.  
That helps filter, suggest, and match Sets to Builds that share intent.  
Primary journey: compose by attach and optional slot pins.  
Secondary journey: curate a library so compose is faster.

## 3. Shape

| Aspect | Rule summary |
| --- | --- |
| Ownership | Private per user. No sharing in initial scope. |
| Types | Weapon, Armor, Mod, Pair, Fashion. Each type has its own slots. |
| Slots | At most one item per domain slot. Empty slots allowed while editing. |
| Min (Weapon / Armor) | Two or more items to **save** and to **attach**. |
| Min (Mod) | Mods on two or more armor pieces to **save** and to **attach**. |
| Pair complete | Exotic weapon **and** exotic armor required to save and attach. |
| Class | Armor Set is class-bound. Mod Set is not. |
| Armor set bonus | Armor Set may set an optional **armor set bonus constraint** (family + 2pc or 4pc target). |
| Synergy Types | Weapon, Armor, Mod, Pair may designate zero or more Types (`type` + optional `subType`). Same vocabulary as Builds. |
| Fashion + synergies | Fashion Sets do not designate Synergy Types. |
| Exotic (set) | At most one exotic weapon in a Weapon Set. At most one exotic armor in an Armor Set. |
| Attach | Live (default) or snapshot. One live Set per type per variant. Set must pass save rules to attach. |
| Tags | Filter metadata only. Not Synergy Types. Not identity. |
| Delete | Blocked while attached. Same delete path everywhere. |
| Lifecycle | One lifecycle for every entry point. |

## 3a. Destiny constraints (hard vs soft)

Destiny rules the product **must** enforce on Sets.  
Product package rules (minimums, lifecycle) are separate and listed in §3 and §6.

### Hard on Set save and fill

| Constraint | Applies to | Rule |
| --- | --- | --- |
| **Legal weapon bucket** | Weapon Set | Item in primary / special / heavy must match that bucket. Illegal item is not selectable. Save rejects illegal kits. |
| **Legal armor slot** | Armor Set | Item in helmet / arms / chest / legs / class item must match that slot. |
| **Armor class** | Armor Set | Items and attach must match the Set class (Titan, Hunter, Warlock). |
| **Armor set bonus (when set)** | Armor Set | If the user sets a bonus constraint, non-exotic pieces must belong to that bonus family. Piece count must meet the target tier (2 or 4) on save and attach. |
| **One exotic weapon** | Weapon Set | At most one exotic weapon across all slots. |
| **One exotic armor** | Armor Set | At most one exotic armor across all slots. Exotic class item counts as exotic armor. |
| **Pair slots** | Pair Set | Only exotic weapon + exotic armor. Both required on save and attach. |
| **Pair vs build exotic armor** | Pair Set | Pair exotic armor must match build exotic armor when the build has one set. |
| **Mod energy** | Mod Set | Total mod cost per armor piece must not exceed capacity (10 if tier ≤4; 11 if tier 5 when known). |
| **Mod legality** | Mod Set | Illegal plugs cannot save. Slot-scoped mods must match the armor piece. |
| **Weapon perk validity** | Weapon Set | Selected perks must be valid for the item in the manifest. |
| **One item per slot** | All typed Sets | At most one active item (or legal plug set for mods) per domain slot. |

### Hard on UI (always)

| Constraint | Rule |
| --- | --- |
| **No illegal pick** | Where pickers exist, the UI must not offer choices that violate hard Destiny rules above. |
| **Save off when hard-blocked** | Primary Save stays disabled while a known hard Destiny violation remains on the Set. |
| **API authoritative** | API rejects the same violations if the client is wrong. |

### Soft only (do not block Set save)

| Topic | Rule |
| --- | --- |
| Weapon element vs subclass | Soft / synergy-based. No hard element lock on the Set. |
| Activity-gated mods | May save. Soft warning allowed. |
| Catalyst / deepsight | Display only on items. Do not gate Set save. |
| Empty capacity encouragement | Soft UI only. |
| Synergy Type nudge | Soft UI only. |
| Armor set bonus coverage (no constraint) | Soft display of 2pc/4pc from filled pieces when no constraint is set. |
| Exotic vs armor set bonus | Soft warn when an exotic piece prevents the target bonus. |

### Not Set-owned (variant / build)

| Topic | Owner |
| --- | --- |
| Dual exotic on a full loadout across multiple Sets | [Domain Variant](/prd/domain-variant/) / compose (DBR-CMP-007 loadout) |
| Subclass aspect / fragment capacity | Build / variant kit |
| Exotic ability requirement pins | Build / variant |
| Equip ownership pins | Variant equip-ready |

## 4. In scope / out of scope

**In**

- Create, edit, fill, save, and delete Sets
- One shared lifecycle
- Slot rules and package minimums
- **Destiny hard constraints** on Set fill and save (§3a)
- **Optional armor set bonus constraint** on Armor Sets (family + 2pc/4pc target)
- **Synergy Type designations** on Weapon, Armor, Mod, and Pair Sets
- Filter and suggest Sets by designated Types
- Bridge Set designations to library Synergies (same bridge idea as Builds)
- Rolls and pins on set items
- Attach live or snapshot
- Fashion as non-combat layer
- Pair as exotic convenience
- Armor board base-roll stats

**Out**

- Set designations as **Build** identity (Build keeps its own designations)
- Required library Synergy record before a Set may designate a Type
- Fashion Sets with Synergy Types
- Armor set bonus constraints on Weapon, Mod, Pair, or Fashion Sets
- Dual-exotic **within** a Weapon Set or Armor Set (hard block — not a feature)
- Soft topics as hard blocks (element match, catalyst, activity mods)
- Vault transfer product
- Auto-apply optimizer without confirm
- A second create/edit/delete UI for finish or attach

## 5. Success

| Signal | Pass when |
| --- | --- |
| Compose | User attaches Sets without unresolved slot conflicts |
| Package min | System rejects under-min Weapon, Armor, or Mod saves |
| Synergy Types | User can designate Types on Weapon, Armor, Mod, Pair; filter and attach suggest by Type |
| Destiny hard | Exotic limits, class, slot legality, mod energy, perk validity enforced on fill and save |
| Armor set bonus | When constrained, family membership and 2pc/4pc target hold on save and attach |
| One lifecycle | Create, edit, and delete match from library and from Build |
| Library bar | Library readiness includes Sets (with synergies) |
| In-flow | User can open Set lifecycle during compose without a deep library |
