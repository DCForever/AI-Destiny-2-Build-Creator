# Armor Set Bonus — Destiny object

> [!abstract] One-liner
> Collection bonus from a matching armor family at 2-piece and/or 4-piece (manifest set-bonus data).

Hub: [Destiny Objects](/prd/destiny-objects/) · Host pieces: [Destiny Armor](/prd/destiny-armor/) · Related: [Destiny Exotic Armor](/prd/destiny-exotic-armor/) (exotic does not count toward tier)

## 1. Definition (Destiny / DIM)

An **armor set bonus** is a Destiny collection effect when enough pieces of one **armor family** are equipped.

| Term | Meaning |
| --- | --- |
| **Bonus family** | Manifest set-bonus definition (name, member pieces, tier effects) |
| **2-piece (2pc)** | Effect at two contributing member pieces |
| **4-piece (4pc)** | Effect at four contributing member pieces |
| **Member piece** | Legendary (or other non-exotic) armor item that belongs to the family |
| **Contributing count** | Number of **member** pieces on the Set/loadout that count toward the bonus |

Typical tiers are **2** and **4**. Follow game data if a family differs — do not invent tiers.

DIM shows set name and 2pc/4pc effect text on armor and loadouts.

### Two product surfaces (do not conflate)

| Surface | What it is | Hard? |
| --- | --- | --- |
| **Destiny object** (this note) | The bonus family + effects + membership | Data truth |
| **Armor Set constraint** | Optional goal on an Armor Set: **family + target tier** (2 or 4) | **Hard when set** (BR-SET-050+) |
| **Soft coverage** | Detected 2pc/4pc from filled pieces when **no** constraint | Soft only |
| **Synergy link** | Evidence kind `armor_set_bonus` | Soft coverage / required-link pins as Synergy rules |

### Armor Set constraint (hard when set)

| Rule | ID |
| --- | --- |
| Zero or one constraint per Armor Set | BR-SET-050 |
| Constraint = family + target tier (2 or 4) | BR-SET-051 |
| Only Armor Sets | BR-SET-052 |
| No constraint → no family required on save | BR-SET-053 |
| Every **non-exotic** filled piece must be a family member | BR-SET-054 |
| Contributing member count ≥ target on **save and attach** | BR-SET-055 / 055a |
| **Exotic does not count** toward tier | BR-SET-056 |
| Soft-warn when exotic blocks target | BR-SET-056a |
| Pickers filter/prefer members; allow exotic under exotic rules | BR-SET-057 |
| UI prevents illegal non-member non-exotic fill | BR-SET-057a |
| Codes: `ARMOR_SET_BONUS_MISMATCH`, `ARMOR_SET_BONUS_INCOMPLETE` | BR-SET-061 |

### Contributing pieces (count rules)

| Piece | Counts toward tier? |
| --- | --- |
| Non-exotic **member** of the family | **Yes** |
| Non-exotic **non-member** | Illegal when constrained (mismatch) |
| **Exotic** armor (any slot, incl. class item) | **No** (does not contribute; may soft-warn) |
| Empty slot | No |

Example: 4pc target with one exotic + three members → **incomplete** (3 &lt; 4).  
4pc target with four members + no exotic → complete.  
4pc target with four members + exotic in fifth slot is impossible (only five slots; exotic replaces a member) → soft-warn that exotic blocks 4pc.

### Synergy

| Rule | Meaning |
| --- | --- |
| Link kind | `armor_set_bonus` |
| Target | **Bonus family** (not a single armor item) **plus a target tier** (**2** or **4**) on the link |
| Soft coverage | Loadout/Set has contributing members activating a tier of that family; UI may show progress vs linked tier |
| Required | May mark required; satisfaction when resolved loadout has contributing members **≥ link target tier** (or higher). Still needs equip-ready pins path per [Domain Variant](/prd/domain-variant/) — DO-ASB-016 |
| Tier vs data | Target tier must be a tier the family **defines** (do not require 4pc if data has only 2pc). Prefer pickers that only offer valid tiers for that family |
| Not the same as | Armor Set **constraint** (package goal on a Set). Same vocabulary (family + 2/4) but different owner and lifecycle |

## 5. Hard vs soft

### Hard

| Rule | Where |
| --- | --- |
| Constrained Set: non-member non-exotic piece | Fill / save / attach |
| Constrained Set: member count &lt; target tier | Save / attach |
| Constraint only on Armor Sets | Set type rules |

### Soft

| Topic | Rule |
| --- | --- |
| No constraint | No family required; optional coverage display |
| Exotic blocks bonus | Soft warn only |
| Variant / loadout coverage | Soft guidance |
| Synergy evidence | Soft unless required-link gate |

### Object rules

| ID | Rule |
| --- | --- |
| DO-ASB-001 | Armor set bonus is a **family + tier effects** object from Destiny data — not a single armor item. |
| DO-ASB-002 | **Constraint** (family + target tier) is optional on **Armor Sets only**; hard when set. |
| DO-ASB-003 | Without a constraint, no bonus family is required to save an Armor Set. |
| DO-ASB-004 | When constrained, every **non-exotic** filled piece must be a **member** of the family. |
| DO-ASB-005 | Contributing member count must meet target **2** or **4** on save and attach. |
| DO-ASB-006 | **Exotic armor does not count** toward the contributing tier. |
| DO-ASB-007 | Soft-warn when an exotic likely blocks the target tier. |
| DO-ASB-008 | UI shows coverage (count vs target) on Armor Set detail when constrained; may show detected coverage when unconstrained. |
| DO-ASB-009 | Presentation: family name + 2pc/4pc text; progress when composing. |
| DO-ASB-010 | Hashes never primary UI (footer addendum only). |
| DO-ASB-011 | Synergy link kind `armor_set_bonus` targets the **bonus family** plus a **target tier** (2 or 4) on the link. |
| DO-ASB-012 | Constraint is **not** Set type and is **not** Build identity. |
| DO-ASB-013 | Clear/change constraint uses shared Set lifecycle. |
| DO-ASB-014 | Do not invent families, members, or tier effects — manifest / loaded data only. |
| DO-ASB-015 | Armor **detail** shows this piece’s family effects or explicit “no set bonus” ([Destiny Armor](/prd/destiny-armor/) DO-ARM-001). |
| DO-ASB-016 | **Required** `armor_set_bonus` links: satisfied when contributing member count on the resolved loadout is **≥ the link’s target tier** (2 or 4). Higher count always satisfies a lower target (4pc meets a 2pc link). |
| DO-ASB-017 | Link target tier must be a tier the family **defines** in data. UI offers only valid tiers for that family. |
| DO-ASB-018 | Soft (non-required) coverage may still show any active tier; required checks use the **link target tier**. |
| DO-ASB-019 | Armor Set constraint and Synergy link both use family + tier vocabulary but are **independent** — setting one does not auto-create the other. |
