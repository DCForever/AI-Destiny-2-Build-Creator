# Weapon — Destiny object

> [!abstract] One-liner
> Equippable combat weapon: damage, ammo, inventory slot, type, frame, sockets, and perks.

## 1. Definition (Destiny / DIM)

A **weapon** is a Destiny inventory item equipped in a weapon slot to deal damage.

DIM models it as an inventory item with:

- **Damage type** (Kinetic / Solar / Arc / Void / Stasis / Strand / …)
- **Ammo** (Primary / Special / Heavy)
- **Inventory bucket / slot** (Kinetic / Energy / Power)
- **Weapon type** (Auto Rifle, Hand Cannon, …)
- **Frame / archetype** (Adaptive Frame, …)
- **Tier** (including Exotic)
- **Sockets** (perks, origin trait, mods, masterwork, cosmetics, trackers, …)
- **Power** and craft/enhanced state when relevant
- **Exotic catalyst** (when the weapon is exotic and has a catalyst) — progress, insert state, and catalyst-granted plug/effects when known

### Three product layers

| Layer | Meaning | Example |
| --- | --- | --- |
| **Identity** | Manifest item (hash) | Fatebringer |
| **Instance** | Owned copy with plugs + power | Vault copy with specific roll |
| **Desired roll** | Wishlist: identity + chosen plugs, no instance | Planning a roll not owned |

Do not confuse inventory **slot** (Kinetic/Energy/Power) with **ammo** (Primary/Special/Heavy).  
Our Synergy types use both: `weapon_slot` vs `ammo` ([Domain Synergy](/prd/domain-synergy/)).

## 2. Presentation (DIM North Star)

### Always (any dense readout)

| Show | How |
| --- | --- |
| Item | Icon + rarity frame |
| Damage | Element glyph |
| Ammo | Ammo glyph |
| Identity name | Tooltip / detail primary text; list rows icon-first (DBR-UI-005) |

### Detail surfaces (Catalog detail, Set item detail, compare)

Match DIM **Weapon Overview** density where practical:

| Block | Content |
| --- | --- |
| Header | Icon, name, type, frame, tier/exotic, power (if instance) |
| Glyphs | Damage, ammo, slot |
| Perk UI — **selected** | Plugs on this instance or desired roll |
| Perk UI — **can roll** | For each roll column, **all valid options** from the weapon’s perk pool (manifest), not only the selected plug |
| Craft UI — **possible crafted** | When the weapon is craftable: show **possible crafted options** (level/unlock tiers, enhanced perks, shaped choices the game allows) — not only the current craft state |
| Hotspot | Perk popup copy (see `Weapon Perk Info Popup.png`) for selected **and** pool / craft options |
| Craft state | Crafted/enhanced badges when this instance or desired roll is shaped |
| **Acquire / farm** | Where the item can be obtained, **when Destiny/manifest (or trusted game data we already load) provides it** |
| **Exotic catalyst** | When the weapon is exotic **and** data says a catalyst exists: status + catalyst effect/plug callout (see §5 Catalyst) |
| Extras | Masterwork, weapon mod if product shows them |

**Can-roll, possible crafted options, acquire/farm (when data exists), and exotic catalyst (when applicable) are required on detail**, not on icon-only Set slot rows.

### List / grid rows (Catalog list, Set slot chips)

| Surface | Show on row | Detail only |
| --- | --- | --- |
| **Weapon Set slot row** | Item **icon** only (+ exotic badge if exotic) | All perks, full DIM-style grid |
| **Catalog list row** | Icon + key glyphs (damage/ammo); exotic badge | Full perk UI |
| **Masterwork / weapon mod** | **Small glyph** on rows when known | Full treatment on detail |
| **Exotic** | Same as legendary + **exotic badge**; intrinsic/trait **callout on detail** | Expanded exotic overview on detail |
| **Exotic catalyst** | **Small status glyph** on rows when known (e.g. complete / incomplete / missing) | Full catalyst block on detail |

**Diverge from DIM product (not presentation):** no vault notes, tags, lock/favorite as product requirements; no DIM LO as compose.

### Hashes (never primary UI)

| ID | Rule |
| --- | --- |
| DO-WPN-010 | **Never** show plug hashes (or item hashes for plugs) as primary UI: not on rows, not as perk labels, not as the main detail headline. |
| DO-WPN-011 | Primary copy is always the **readable name** (and icon). Fallback “Unknown perk” if the name is missing — still not a bare hash as the title. |
| DO-WPN-012 | Hashes may appear only as an **addendum at the bottom** of a description / detail footer (e.g. “IDs: plug 1234567890”) for support/debug — collapsed or secondary, never inline in the perk grid. |
| DO-WPN-013 | Search that matches a hash may still **find** the plug; the result row still shows the **name**, not the hash as the primary label. |

### Density by surface

| Surface | Weapon detail depth |
| --- | --- |
| Catalog list | Icon + glyphs; exotic badge; MW/mod glyph if known |
| Catalog / Set **detail** | DIM-like overview + **selected** perks, **can-roll pool**, **possible crafted options** when craftable, **exotic catalyst** when applicable, and **acquire/farm** when data exists; exotic trait callout |
| Set **slot row** | **Icon only** (+ exotic badge); optional tiny catalyst glyph when known; no full perk text |
| Loadout / equip readout | Icon strip; expand for detail |
| Perk hotspot | Popup like DIM perk info (`Weapon Perk Info Popup.png`); catalyst plug uses same hotspot pattern |

### Catalog weapons browse — default sort

When browsing weapons (identities / result list), default order:

1. **Inventory slot** (Kinetic → Energy → Power)  
2. **Exotic** (exotics before legendaries, or grouped)  
3. **Ammo** (Primary → Special → Heavy)  
4. **Archetype / frame**  

User may change sort when product offers it.  
Owned **instances** of one identity: still prefer higher power when choosing a copy for pin (within that identity).

## 5. Hard vs soft

### Hard

| Rule | Where |
| --- | --- |
| Item must match legal weapon bucket for the Set/variant slot | Set fill, constrained Catalog pick |
| At most one exotic weapon per Weapon Set | [Domain Set](/prd/domain-set/) |
| At most one exotic weapon on resolved loadout | [Domain Variant](/prd/domain-variant/) |
| Plugs must be valid for item on save | Set / roll validation |
| Pin required for equip on applied slots | [Domain Variant](/prd/domain-variant/) |

### Soft / display-only

| Topic | Rule |
| --- | --- |
| Weapon element vs subclass element | Soft / synergy-based (DBR-STAT-007) |
| **Exotic catalyst** | **Display + soft warn only** — never blocks save, attach, or equip (DBR-ROLL-007; DO-WPN-040+) |
| Deepsight / pattern | Display only (DBR-ROLL-008) |
| Champion intrinsic counters | Display / soft guidance when product shows them |

### Can-roll (product hard for detail)

| ID | Rule |
| --- | --- |
| DO-WPN-001 | Weapon **detail** must show, for each relevant roll column, **what can roll** (manifest perk pool), not only the selected plug. |
| DO-WPN-002 | Selected plug is visually distinct from other pool options in that column. |
| DO-WPN-003 | Can-roll uses manifest socket definitions for that item (and curated/craftable tables when the game provides them). |
| DO-WPN-004 | If pool data is missing, show selected only and an honest “pool unavailable” state — do not invent perks. |
| DO-WPN-005 | Set **slot rows** stay icon-only; can-roll is **not** required on the row. |
| DO-WPN-006 | Wishlist / desired-roll edit may pick from the can-roll pool for that column. |
| DO-WPN-007 | Exotic fixed traits still appear; “can roll” for fixed sockets is the fixed set (often one). |

### Possible crafted options (product hard for detail)

| ID | Rule |
| --- | --- |
| DO-WPN-020 | When a weapon **can be crafted** (shaped), weapon **detail** must show **possible crafted options**, not only the current craft state of an instance. |
| DO-WPN-021 | Possible crafted options include, as data allows: craft/unlock **levels**, **enhanced** perk choices, and other shaped selections the recipe exposes. |
| DO-WPN-022 | Selected craft state (if any) is visually distinct from other possible crafted options. |
| DO-WPN-023 | Wishlist / desired-roll edit may choose from possible crafted options when planning a shaped roll. |
| DO-WPN-024 | If the weapon is **not** craftable, do not show an empty craft panel; omit craft UI. |
| DO-WPN-025 | If craft recipe data is missing, show honest “craft options unavailable” — do not invent unlocks. |
| DO-WPN-026 | Set **slot rows** stay icon-only; possible crafted options are **not** required on the row (same as can-roll). |
| DO-WPN-027 | Craft option labels use **readable names** (and icons). Plug hashes only as description footer addendum (DO-WPN-010–013). |
| DO-WPN-028 | Can-roll pools and crafted options may appear together on detail; they must stay distinguishable (dropped roll vs shaped path). |
| DO-WPN-029 | **Craftable is not legendary-only.** Exotic weapons that are craftable (shaped) in Destiny data **also** get possible-crafted detail treatment (DO-WPN-020–028). Exotic tier does **not** suppress craft UI. |
| DO-WPN-029a | On a craftable exotic, **selected** plugs remain the primary “current craft / equipped shape” readout (do not duplicate a separate current-craft list that only repeats the perk grid). |
| DO-WPN-029b | Possible crafted options on craftable exotics may include, as data allows: enhanced exotic trait choices, level unlocks, and other shaped selections — still never invent options. |

### Acquire / farm (when Destiny data has it)

| ID | Rule |
| --- | --- |
| DO-WPN-030 | When loaded Destiny data already includes **where the weapon can be acquired or farmed**, weapon **detail** must show that information. |
| DO-WPN-031 | Sources may include (as data provides): activity/drop source, playlist, vendor, quest, seasonal craft/pattern, raid/dungeon, world drop, or equivalent Bungie/manifest fields we already resolve. |
| DO-WPN-032 | **Do not invent** farm locations. If no source data is available, omit the acquire block or show honest “source unknown” — never guess. |
| DO-WPN-033 | Prefer **readable source names and icons** (activity/vendor glyphs). Same hash rule: no bare hashes as primary labels (DO-WPN-010–013). |
| DO-WPN-034 | Acquire/farm is **detail** content. Not required on icon-only Set slot rows. |
| DO-WPN-035 | If multiple sources exist, list all known sources from data (or a clear primary + “more” if UI density requires). |
| DO-WPN-036 | Retired/unavailable sources: show when data marks them unavailable or seasonal-ended, with honest labeling — do not present them as current farms. |

### Exotic catalyst (product)

Exotic **catalysts** upgrade many exotic weapons (extra perk, masterwork-style stats, or other game-defined effects). They are **first-class on the Weapon object** for presentation and soft guidance — **not** a separate Destiny object note and **not** a hard compose gate.

#### What counts

| Case | Product treatment |
| --- | --- |
| Exotic with a known catalyst in data | Show catalyst block on **detail**; status when instance/progress known |
| Exotic with **no** catalyst in data | Omit catalyst UI entirely (do not show empty “no catalyst” noise unless useful) |
| Legendary / non-exotic | No exotic catalyst UI |
| **Craftable exotic** | Craft UI (possible crafted) **and** catalyst UI are **independent** when both exist in data: shaping does not remove catalyst presentation; catalyst does not suppress craft presentation |
| Catalyst socket on instance grid | Own **column** in the perk/socket grid when present (with intrinsic / traits), same density pattern as other columns. On craftable exotics, catalyst insert/completion may change which catalyst-related plugs appear on the grid — show selected distinctly; possible catalyst-related craft options belong under possible crafted when the recipe exposes them |

#### Status model (soft — DBR-ROLL-007)

| Status | Meaning | UI |
| --- | --- | --- |
| **Unacquired** | Catalyst not obtained | Soft label/warn on detail; optional row glyph |
| **Unfinished** | In progress / objectives incomplete | Soft warn |
| **Complete, unequipped** | Catalyst done but not inserted on this copy | Soft warn |
| **Equipped / inserted** | Catalyst active on this instance | Neutral/success treatment |

Map game/API states into this vocabulary honestly. If progress data is missing, show catalyst **definition** (name/effect) without inventing completion.

#### Product use

| Surface | Behavior |
| --- | --- |
| Catalog / Set **detail** | Catalyst name, effect/description, status when known; progress or acquire notes **when data exists** |
| Perk / socket grid | Catalyst as its own column when the copy/socket model has one |
| Set **slot row** | Optional **small glyph** only; no full catalyst text |
| Wishlist / desired roll | May record “prefer catalyst complete” as display intent when product supports it — still **does not** gate save |
| Equip / Set save | **Never** blocked solely by incomplete/missing catalyst |
| Soft guidance | Incomplete catalyst may appear in soft coverage / warnings |
| Synergy | No separate `catalyst` link kind in v1. Catalyst-granted **trait plugs** (when they are plugs) may still count as `weapon_perk` evidence like other exotic traits (DBR-SYN-014) when linked by that plug — status itself is not a link target |

#### Object rules

| ID | Rule |
| --- | --- |
| DO-WPN-040 | When an exotic weapon **has a catalyst in loaded data**, weapon **detail** must account for it: name/effect (when known) and **status** when progress/instance data exists. |
| DO-WPN-041 | Catalyst status uses the soft vocabulary: unacquired / unfinished / complete-unequipped / equipped (or honest subset from data). Aligns with DBR-ROLL-007. |
| DO-WPN-042 | Catalyst is **display and soft-warn only**. Incomplete, missing, or unequipped catalyst **must not** block Set save, variant save, attach, or equip/export. |
| DO-WPN-043 | On the instance (or roll) **socket grid**, present catalyst as its **own column** when the socket exists — usually single-option when inserted/available; do not hide it inside an unlabeled “other” dump when kind is known. |
| DO-WPN-044 | Selected/inserted catalyst plug is visually distinct from empty/unavailable catalyst state. |
| DO-WPN-045 | **Do not invent** catalyst objectives, drop sources, or completion. If data lacks progress or quest steps, omit those fields or show “progress unknown.” |
| DO-WPN-046 | When data includes catalyst acquire/progress sources, show them on detail (same honesty rules as DO-WPN-030–036). |
| DO-WPN-047 | Set **slot rows** may show a **small catalyst status glyph** when known; full catalyst copy stays on detail. |
| DO-WPN-048 | Legendary weapons and exotics **without** a catalyst in data do not get a fake catalyst panel. |
| DO-WPN-049 | No Synergy link kind `catalyst` in v1. Catalyst-granted plugs may participate as `weapon_perk` when they are trait plugs; link the plug, not a free-form “has catalyst” flag. |
| DO-WPN-050 | Catalyst labels use **readable names** (and icons). Plug hashes only as description footer addendum (DO-WPN-010–013). |
| DO-WPN-051 | Wishlist may express a desired catalyst state for planning/display only; equip-ready still depends on pins, not catalyst completion. |
| DO-WPN-052 | **Craftable exotics:** when data says an exotic is craftable **and** has a catalyst, detail must support **both** (possible crafted + catalyst status/effect). Neither feature replaces the other. |
| DO-WPN-053 | Completing or inserting a catalyst may **change** the exotic’s active plugs / catalyst column on that instance. Present the **current** catalyst status and selected plugs honestly; do not assume “exotic = fixed one-roll forever” when craft or catalyst data allows change. |
| DO-WPN-054 | Soft-only for catalyst (DO-WPN-042 / DBR-ROLL-007) still applies to craftable exotics: catalyst state never hard-gates Set/variant save or equip. |
