# Build — area product description

> [!abstract] One-liner
> Create and maintain class-bound Builds: intent → compose → equip UI.

Catalog: [Products](/prd/products/) · Domains: [Domain Build](/prd/domain-build/) (identity SSoT) · [Domain Variant](/prd/domain-variant/) (variant composition SSoT)

## 1. Role in the product

| Field | Content |
| --- | --- |
| **Product role** | **Primary product spine** |
| **One-liner** | Create and maintain class-bound Builds: designate intent, compose variants via sets/overrides, soft-guide quality, equip or export when equip-ready. |
| **Primary journey** | Owns **intent → compose → equip** end-to-end (with Settings for sync/auth, Catalog/Sets/Synergy as suppliers). |

## 2. Users & jobs

- **Primary job:** Leave a session with a stable Build identity and at least one coherent default combat loadout, with a path to equip/export.
- **Secondary jobs:** Manage variants; finish armor/weapons/mods; see soft coverage; pin owned instances; resolve conflicts/stale pins.
- **Not for:** Long-term vault organization (DIM), free-form inventory transfer UI, treating tags as build identity.

## 3. In scope

- Build library (list, filters, search, selection, **delete**, **duplicate**)
- Create: class fixed after create; tree; **≥1 Type before first save**; optional exotic armor / pinned Super; exotic weapon variant-level by default
- Identity edit (Types, exotic armor item, promote/demote shared exotic weapon, pin/unpin Super): **confirm in-place** or **fork** (fork clones entire Build)
- Tree change: confirm/fork then **wipe Subclass areas** to empty legal baseline on variants
- Build save re-checks default variant compose + required pins
- Name: auto re-derive if still system-derived; concept tags filter only; soft stats Build-level
- Default + additional variants; notes; naming
- **Variant composer always shows four areas:** General · Subclass · Armor + Mods Sets · Weapons Set ([Domain Variant](/prd/domain-variant/) BR-VAR-030–039)
- Add variant: optional clone, else empty with default **ghost** preview
- Set as default; complete-default flow when incomplete
- Equip/DIM: sticky chrome + General readiness summary (compose / required / equip-ready)
- Sets areas (**Armor + Mods**, **Weapons**): three **distinct** ops — **Create Set**, **Edit Set**, **Attach Set(s)** ([Domain Variant](/prd/domain-variant/) BR-VAR-060–067)
- Create/Edit → shared [Area Sets](/prd/area-sets/) lifecycle only (same as `/sets`; no lite form)
- Attach → separate picker/panel (live/snapshot, replace-by-type); not mixed with create/edit fields
- Slot overrides in the correct area; finish walkthrough (slot-first; armor optimize path)
- Attach only when the Set would pass save rules; one live Set per type (replace-by-type)
- **Starting** library Synergy create/edit — **enters [Area Synergy](/prd/area-synergy/) shared lifecycle** (BR-SYN-020–026); no Build-local Synergy editor fork
- Soft guidance / coverage; soft stat targets
- Wishlist desired rolls vs equip-ready pins; equip / DIM export entry when ready
- In-flow create of sets/synergies when library is thin

## 4. Out of scope / non-goals

- Cloning DIM Loadout Optimizer as the **compose** path (`DBR-UI-002`)
- Full Bungie transfer/vault product (equip may transfer as needed; not a vault app)
- Auto-applying optimizer or soft suggestions without confirm
- Making deep library a hard gate to start composing (`DBR-PUR-004`)

## 7. Presentation notes

- **Compose workflow is product-owned** (not DIM LO).  
- **Variant chrome:** four named areas always visible or always one hop away (tabs/sections). Do not collapse into one undifferentiated scroll without area headers.  
- **Sticky** equip/export chrome; General shows readiness summary. Empty non-default areas may show default **ghost** when creating empty variants.  
- Sets areas: separate entry points for Create, Edit, and Attach — do not overload one control.  
- **Readouts** of gear, perks, mods, stats should still feel DIM-familiar: dense, **icon-first** (`DBR-UI-001`, `DBR-UI-005`).  
- Repo refs: `docs/dim-reference-screenshots/`.
