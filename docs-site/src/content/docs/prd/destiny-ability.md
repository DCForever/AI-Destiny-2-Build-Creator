# Ability — Destiny object

> [!abstract] One-liner
> Subclass action choice: Super, melee, grenade, class ability, or movement.

Hub: [Destiny Objects](/prd/destiny-objects/) · Parent: [Destiny Subclass](/prd/destiny-subclass/) · Sibling: [Destiny Aspect](/prd/destiny-aspect/) · [Destiny Fragment](/prd/destiny-fragment/)

## 1. Definition (Destiny / DIM)

An **ability** is a selectable subclass action for one **class + element/tree**.

### Five kinds (always product vocabulary)

| Kind | Role |
| --- | --- |
| **Super** | Ultimate ability |
| **Melee** | Charged / subclass melee choice |
| **Grenade** | Grenade choice |
| **Class ability** | Class-specific (rift, barricade, dodge, …) |
| **Movement** | Movement mode (glide, lift, …) where the tree offers choices |

DIM loadouts show ability icons in the subclass kit beside aspects/fragments.

### Product placement

| Concern | Owner |
| --- | --- |
| **Tree / element** | [Domain Build](/prd/domain-build/) — shared; abilities must match this tree |
| **Ability selections** | [Domain Variant](/prd/domain-variant/) — **Subclass** area only; may differ per variant |
| **Build-pinned Super** | [Domain Build](/prd/domain-build/) — optional **identity**; pin/unpin = confirm or fork (DBR-ID-007 / 007a) |
| **Exotic-required abilities** | Auto-propose pins; user confirms; mismatch hard (DBR-SUB-005) |
| **Non-pinned abilities** | Variant-local; no Build confirm/fork |

**Not** the same as Synergy **designation types** `melee` / `grenade` / `super` (playstyle tags).  
Those are Type designations on a Synergy. Ability **link kinds** point at ability definitions (see §4).

## 4. Product use

| Product | How abilities appear |
| --- | --- |
| [Domain Build](/prd/domain-build/) | Shared tree; optional **build-pinned Super** (identity); mini kit strip shows five abilities |
| [Domain Variant](/prd/domain-variant/) | **Only** edited in **Subclass** area (subject to pin locks) |
| Default complete | **Super + melee + grenade** required; class ability + movement **shown**, required only if exotic forces (DO-SUB-009–010) |
| [Domain Synergy](/prd/domain-synergy/) | Link kinds: `melee`, `grenade`, `super` only — **not** class ability or movement in v1 (BR-SYN-019a) |
| [Area Catalog](/prd/area-catalog/) | Universal pick by kind (scoped when in kit compose) |
| Soft stats | May contribute to loadout estimate |

### Create / tree-change baseline

After create or tree change: abilities cleared to **empty legal baseline** (BR-BLD-040a).  
User re-selects. Build-pinned Super, if still valid for the new tree, may re-apply per Build identity rules; if invalid for new tree, identity pin must be cleared via confirm/fork path (implement aligns with identity field validity).

### Build-pinned Super

| Event | Product behavior |
| --- | --- |
| Super not pinned | Each variant may pick its own Super in Subclass area |
| Pin Super | Identity change → **confirm or fork**; all variants constrained to that Super |
| Unpin Super | Identity change → confirm or fork; variants free again |
| Edit Super while pinned | Change pinned Super value is identity (confirm/fork), not a silent per-variant edit |

### Exotic-required abilities

| Step | Behavior |
| --- | --- |
| Exotic gear implies required ability | System **auto-proposes** pin(s) |
| User confirms | Pins apply; UI shows locked/badge |
| User declines / mismatches | **Cannot save** while required ability is wrong (DBR-SUB-005) |

Applies to whichever kind the exotic requires (often Super or melee; follow game data — do not invent).

### Ability change mid-edit (non-pinned)

| Event | Product behavior |
| --- | --- |
| Swap melee / grenade / class / movement / unpinned Super | Variant-local; no Build confirm/fork |
| Illegal for tree after tree change | Already wiped by baseline; picker only shows legal options |

## 5. Hard vs soft

### Hard

| Rule | Where |
| --- | --- |
| Abilities must match Build class + tree + kind | Variant Subclass / validation |
| Illegal ability for kit cannot save | Variant (DBR-SUB-004) |
| Exotic-required ability mismatch blocks save | Variant / pins (DBR-SUB-005) |
| Default complete needs Super + melee + grenade | Variant §3.2 / DO-SUB-009 |
| Pin/unpin Super is identity (confirm/fork) | Build (DBR-ID-007a) |

### Soft

| Topic | Rule |
| --- | --- |
| Class ability / movement empty on default | Allowed unless exotic forces |
| Synergy ability link coverage | Soft on non-default |
| Cooldown / charge display | Optional soft detail; not compose gate |
| Prismatic | Same product rules as other trees (DBR-SUB-002); own ability pools |
| Soft stat affinity | Display / estimate only |

### Object rules

| ID | Rule |
| --- | --- |
| DO-ABL-001 | Ability is a **child plug** of [Destiny Subclass](/prd/destiny-subclass/); five kinds: Super, melee, grenade, class ability, movement. |
| DO-ABL-002 | Edited only in Variant **Subclass** area (DBR-SUB-003), subject to pin locks. |
| DO-ABL-003 | Must match Build **class + tree + kind**; Prismatic does not widen to all-element abilities. |
| DO-ABL-004 | Presentation is **icon-first**; **all five kinds always shown** in Subclass area. |
| DO-ABL-005 | **Default complete** requires Super, melee, and grenade selected (align DO-SUB-009). |
| DO-ABL-006 | Class ability and movement are **shown and editable**; **not** required for default complete unless exotic forces (align DO-SUB-010). |
| DO-ABL-007 | **Build-pinned Super** is Build identity; pin/unpin/change pinned value → confirm or fork. |
| DO-ABL-008 | Non-pinned ability changes are **variant-local**; no Build confirm/fork. |
| DO-ABL-009 | Exotic-required abilities: auto-propose pins; confirm; mismatch blocks save (DBR-SUB-005). |
| DO-ABL-010 | Pinned Super and exotic-required abilities are **visually distinct** (locked/badge) — align DO-SUB-006. |
| DO-ABL-011 | Hashes never primary UI (footer addendum only). |
| DO-ABL-012 | Catalog/search may match hash; result row still shows **name + icon**, not bare hash. |
| DO-ABL-013 | Synergy **link** kinds for abilities in v1: `melee`, `grenade`, `super` only — not class ability or movement. |
| DO-ABL-014 | Ability link kinds are **not** Synergy designation types of the same names (context: link vs type). |
| DO-ABL-015 | Cooldown/charge is **not** a compose completeness requirement in v1. |
| DO-ABL-016 | Build library mini kit strip includes **all five** ability icons (DO-SUB-011). |

## 6. Out of scope

- Class ability / movement as Synergy link kinds in v1  
- Full ability theorycraft (DPS, cooldown optimizers) as product features  
- Inventing exotic→ability requirements not in game data we load  
- Per-variant tree (forbidden — tree is shared)  
- Treating non-Super abilities as Build identity (except exotic-required pins)
