> [!abstract] One-liner
> Energy-cost plug on armor: combat, general, or tuning mods that grant effects or stats.

## 1. Definition (Destiny / DIM)

An **armor mod** is a socket plug on an armor piece that:

| Role | Meaning |
| --- | --- |
| **Energy cost** | Consumes armor energy toward piece capacity |
| **Effect / stats** | Grants combat effects, resilience, stat bumps, activity perks, etc. |
| **Scope** | Slot-scoped (helmet-only, …) or **general / tuning** (any piece when legal) |

DIM shows mod icons on energy slots per piece with remaining capacity.

### Categories (product vocabulary — not separate objects)

| Category | Notes |
| --- | --- |
| **Combat / armor-slot** | Often piece-scoped (helmet, arms, …) |
| **General** | May sit on any piece when game allows |
| **Tuning / artifice-style** | Extra slots or stat plugs when piece supports them |
| **Activity-gated** | Legal to save; soft warning allowed (DBR-MOD-004) |

Do **not** invent category labels beyond what game data supports. Use data-driven socket groups when known.

### Not this object

| Object | Why separate |
| --- | --- |
| [Destiny Weapon Perk](/prd/destiny-weapon-perk/) / weapon combat mod | On **weapons**, not armor energy |
| [Destiny Artifact Perk](/prd/destiny-artifact-perk/) | Seasonal artifact tree, not armor sockets |
| Class-item exotic perk config | Exotic armor identity / config — see [Destiny Exotic Armor](/prd/destiny-exotic-armor/) / [Destiny Armor](/prd/destiny-armor/) |

### Energy capacity (hard)

| Armor tier (when known) | Capacity |
| --- | --- |
| ≤ 4 | **10** |
| 5 | **11** |

Unknown tier: treat conservatively in UI when possible; API still rejects over-capacity when tier known (DBR-MOD-001–003).

### Create / empty

A Mod Set may be edited piece-by-piece; **save** requires mods on **two or more** armor pieces (DBR-CMP-009).  
Empty capacity on a piece is fine; soft encourage leftover energy.

## 5. Hard vs soft

### Hard

| Rule | Where |
| --- | --- |
| Sum of mod costs on a piece > capacity → cannot save | Mod Set / validation (`MOD_ENERGY_EXCEEDED`) |
| Illegal plug for piece / socket → cannot save | Mod Set (DBR-MOD-001) |
| Slot-scoped mod on wrong piece → cannot save | Mod Set (BR-SLOT-010b) |
| Mod Set with mods on &lt; 2 pieces → cannot save | Mod Set (`MOD_SET_MIN_SLOTS`) |

### Soft

| Topic | Rule |
| --- | --- |
| Activity-gated mods | May save; soft warning (DBR-MOD-004) |
| Empty remaining energy | Encourage in UI (BR-SLOT-007) |
| Synergy mod coverage | Soft except required-link gate on default |
| Stat contribution | Soft estimate / live detail — not base board |

### Object rules

| ID | Rule |
| --- | --- |
| DO-AMOD-001 | Armor mod is an **energy plug on armor**, not a weapon plug or artifact perk. |
| DO-AMOD-002 | Stored and edited primarily via **Mod Sets** ([Domain Set](/prd/domain-set/)); Variant attaches Mod Sets in Armor + Mods area. |
| DO-AMOD-003 | Energy capacity is **10** (tier ≤4) or **11** (tier 5 when known). |
| DO-AMOD-004 | Over-capacity or illegal plugs cannot save; UI prevents when known. |
| DO-AMOD-005 | Slot-scoped mods must match the armor piece; general/tuning may sit on any legal piece. |
| DO-AMOD-006 | Activity-gated mods may save with soft warning. |
| DO-AMOD-007 | Presentation is **icon-first** with energy cost and used/remaining capacity on placement UI. |
| DO-AMOD-008 | Hashes never primary UI (footer addendum only). |
| DO-AMOD-009 | Synergy link kind `armor_mod` resolves to armor mod definitions. |
| DO-AMOD-010 | Mod grants do **not** change Armor Set **base-roll board** stats (DBR-STAT-008). |
| DO-AMOD-011 | Catalog/search may match hash; result row shows **name + icon**, not bare hash. |
| DO-AMOD-012 | Soft-encourage empty energy; do not hard-block save for leftover capacity. |
| DO-AMOD-013 | Acquire/farm on mod detail when Destiny data provides sources — never invent. |
