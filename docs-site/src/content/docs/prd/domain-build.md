## 1. Definition

A **Build** is a class-bound, private product object.  
It has a stable **identity**.  
It has exactly one **default variant** and may have more variants ([Domain Variant](/prd/domain-variant/)).  
**Primary identity** is designated **Synergy Types**.  
Optional identity: exotic armor **item** (non–class-item), **build-shared** exotic weapon, **build-pinned** Super.  
**Character** is chosen at equip time. Character is not identity.

## 2. Why it exists

Players need one durable kit family across activities and rolls.  
They are not served by a one-shot loadout randomizer.  
Build is the spine of **intent → compose → equip**.  
Library of Sets and Synergies is secondary and supports compose.

## 3a. Constraints (hard vs soft)

### Hard on Build save

| Constraint | Rule |
| --- | --- |
| **≥1 Synergy Type** | Save rejects with `NO_SYNERGY` if zero Types designated |
| **Valid Types** | Types use [Domain Synergy](/prd/domain-synergy/) enum + curated subTypes only |
| **Class** | Build must have a class |
| **Tree** | Build must have a subclass element/tree |
| **Default exists** | Exactly one default variant; never zero variants |
| **Default gates** | Default save follows [Domain Variant](/prd/domain-variant/) compose + required-link pins |
| **Identity change** | Any identity-field change requires confirm or fork — no silent edit |
| **≥1 Type always** | No draft save without Types |
| **Default gates on Build save** | Build save re-validates default Variant gates 1–2 |

### Soft only

| Topic | Rule |
| --- | --- |
| Soft nudge 2–5 Types | Soft; no hard max on Type count |
| Concept tags | Filter only; not identity |
| Soft stat targets | Warning when below; not save block |
| Deep library | Readiness bar; not a gate to create Build |
| Shareable links | Out of v1 |
| Name | Auto re-derive only while still on derived (non-custom) name |

## 4. In scope / out of scope

**In**

- Build library: list, filter, search, open, **delete**, **duplicate**
- Create Build: class, tree, ≥1 Type before first save, optional identity fields, first default variant
- Edit identity (any identity field) with confirm/fork
- Name derive, rename, auto-refresh when still derived
- Concept tags for filter
- Soft stat targets (build-level)
- Notes on Build
- Entry to variant composer and equip/export product entry
- In-flow open of Sets/Synergy lifecycles (no forks)

**Out**

- Tags as identity
- Save without ≥1 Synergy Type (no draft-without-Types)
- Silent identity edits
- Inventory-first product / vault app
- DIM Loadout Optimizer as the compose path
- Multi-tenant sharing / shareable links as v1 requirement
- Full redefinition of Variant/Set/Synergy packs

| BR-BLD-021 | Confirm in-place applies the identity change to this Build and all its variants. |
