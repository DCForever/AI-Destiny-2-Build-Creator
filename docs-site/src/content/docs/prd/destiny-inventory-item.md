# Inventory Item — Destiny object

> [!abstract] One-liner
> Generic Destiny item umbrella (definition + optional instance) when product rules are kind-agnostic.

Hub: [Destiny Objects](/prd/destiny-objects/) · Prefer typed children: [Destiny Weapon](/prd/destiny-weapon/) · [Destiny Armor](/prd/destiny-armor/) · [Destiny Fashion Item](/prd/destiny-fashion-item/) · …

> [!note] DIM reuse
> DIM’s core unit is an **inventory item**: manifest definition + optional live instance.  
> **Product rule:** prefer a **typed** Destiny object whenever the kind is known. Use this note only for cross-cutting rules.

---

## 1. Definition (Destiny / DIM)

An **inventory item** is any Destiny inventory definition the game can place in a bucket, with an optional **owned instance**.

| Layer | Meaning |
| --- | --- |
| **Definition (identity)** | Manifest item hash — “what it is” |
| **Instance** | Owned copy — plugs, power, stats, instance id |
| **Desired / wishlist** | Identity (+ desired plugs) without a pin |

This umbrella covers weapons, armor, fashion, and other kinds at the data layer.  
**Product authoring** should still use specific notes for kind-specific behavior.

### When to use this object vs typed notes

| Use **Inventory Item** | Use **typed** object instead |
| --- | --- |
| Universal search/result rules | Weapon Set slot legality → [Destiny Weapon](/prd/destiny-weapon/) |
| Shared hash / pin / display chrome | Armor energy → [Destiny Armor](/prd/destiny-armor/) / [Destiny Armor Mod](/prd/destiny-armor-mod/) |
| Kind-agnostic Catalog hit | Exotic identity → [Destiny Exotic Armor](/prd/destiny-exotic-armor/) |
| “Any item” filters | Fashion omit → [Destiny Fashion Item](/prd/destiny-fashion-item/) |

Do **not** use this umbrella as a substitute for typed Set slots.

## 2. Presentation (DIM North Star)

### Always (kind-agnostic chrome)

| Show | How |
| --- | --- |
| Item | Icon + rarity frame when known |
| Name | Tooltip / detail primary; list rows icon-first (DBR-UI-005) |
| Kind | Route to typed panel when known |

### Detail

Kind-specific panels take over (weapon perk grid, armor stats, fashion, …).  
Umbrella only states: **name + icon first**; never bare hash as title.

### Hashes (global — apply to all kinds)

| ID | Rule |
| --- | --- |
| DO-ITEM-010 | Never show item/plug hashes as primary UI labels. |
| DO-ITEM-011 | Primary copy is readable **name** + **icon**. Fallback “Unknown item” if name missing — still not bare hash as title. |
| DO-ITEM-012 | Hashes only as **footer addendum** on detail (support/debug). |
| DO-ITEM-013 | Search may match hash; result row still shows name + icon. |

(Aligns with [Destiny Weapon](/prd/destiny-weapon/) DO-WPN-010–013; this note is the kind-agnostic restatement.)

| Soft guidance | Kind-agnostic messaging only when kind unknown |

### Identity vs instance (cross-cutting)

| Rule | Meaning |
| --- | --- |
| Pin | Binds an **instance** for equip-ready |
| Wishlist | May store identity + desired plugs without pin |
| Stale pin | Instance missing after sync → mark stale; re-pin (Variant rules) |

## 5. Hard vs soft

### Hard

| Rule | Where |
| --- | --- |
| When kind is known, **typed** hard rules apply | Sets / Variant / validation |
| Equip needs non-stale pins for applied combat slots | Variant |
| Do not invent item definitions | Data |

### Soft

| Topic | Rule |
| --- | --- |
| Universal sort defaults | Prefer typed sort when facet is kind-specific |
| Acquire/farm | Show when data exists (typed notes may specialize) |

### Object rules

| ID | Rule |
| --- | --- |
| DO-ITEM-001 | Inventory item is the **generic** Destiny item umbrella (definition ± instance). |
| DO-ITEM-002 | Prefer **typed** Destiny objects whenever kind is known. |
| DO-ITEM-003 | Do **not** use this umbrella as a typed Set slot type. |
| DO-ITEM-004 | Definition hash = identity; instance id = owned copy / pin. |
| DO-ITEM-005 | Presentation: icon-first; kind-specific detail when known. |
| DO-ITEM-006 | Synergy v1 has **no** generic `inventory_item` link kind — use typed kinds. |
| DO-ITEM-007 | Hashes never primary UI (DO-ITEM-010–013). |
| DO-ITEM-008 | Acquire/farm when data exists; never invent (global hub rule). |
| DO-ITEM-009 | Kind-specific hard rules always win over umbrella soft defaults. |
