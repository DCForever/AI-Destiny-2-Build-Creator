# Aspect — Destiny object

> [!abstract] One-liner
> Major subclass tree choice: defines part of the play pattern and grants fragment capacity.

Hub: [Destiny Objects](/prd/destiny-objects/) · Parent: [Destiny Subclass](/prd/destiny-subclass/) · Sibling: [Destiny Fragment](/prd/destiny-fragment/) · [Destiny Ability](/prd/destiny-ability/)

> [!note] DIM reuse

> Visual refs: repo `docs/dim-reference-screenshots/Loadout Optimizer - Subclass Picker Part 1.png`, `Part 2.png`.  
> **Product diverge:** aspects are **per-variant kit** under a **Build-owned tree** — not a DIM vault/loadout product.

## 1. Definition (Destiny / DIM)

An **aspect** is a selectable subclass plug for one **class + element/tree**.

It typically:

| Role | Meaning |
| --- | --- |
| **Play pattern** | Major effects that shape how the tree plays |
| **Fragment capacity** | Grants one or more fragment slots (summed across equipped aspects) |
| **Slot plug** | Fills one of a small fixed number of aspect slots on the kit |

DIM shows aspects as icons in aspect slots above the fragment grid.

### Product placement

| Concern | Owner |
| --- | --- |
| **Tree / element** | [Domain Build](/prd/domain-build/) — shared; aspects must match this tree |
| **Aspect selections** | [Domain Variant](/prd/domain-variant/) — **Subclass** area only; may differ per variant |
| **Fragment capacity** | Derived from selected aspects; hard gate on fragment picks |
| **Pins** | Aspects are **not** build-pinned identity (unlike Super when pinned) |

Aspects are **not** Build identity. Changing aspects does **not** require confirm/fork.  
Only tree/class identity changes do (see [Destiny Subclass](/prd/destiny-subclass/), [Domain Build](/prd/domain-build/)).

### Always

| Show | How |
| --- | --- |
| Aspect | Icon + rarity/frame if game provides |
| Identity name | Tooltip / detail primary text |

### Subclass area (Variant) — aspect block

Match DIM subclass picker density where practical:

| Block | Content |
| --- | --- |
| Aspect slots | Fixed slot row (count from game data when known; typically **2**) |
| Selected | Icon in each filled slot |
| Empty | Empty-slot affordance for unfilled required slots |
| Capacity cue | Fragment capacity **granted by this aspect** (and total from all selected) visible near aspect/fragment boundary |
| Picker | Scoped list: only aspects legal for Build **class + tree** |
| Illegal | Disabled or hidden when known illegal for current tree/class |

### Compact / summary

| Surface | Show |
| --- | --- |
| Build library mini kit strip | Aspect icons in the strip ([Destiny Subclass](/prd/destiny-subclass/) DO-SUB-011) |
| Soft guidance | Aspect coverage hints without full builder |
| Catalog list row | Icon-first; element/class glyphs as needed |
| Catalog / pick detail | Name, description, granted capacity, tree/class |

**Hashes:** never primary UI; names/icons first; IDs only as description footer addendum (same global rule as weapons).

## 4. Product use

| Product | How aspects appear |
| --- | --- |
| [Domain Build](/prd/domain-build/) | Not identity; mini kit strip shows selected aspects (from focused/default variant chrome as product defines) |
| [Domain Variant](/prd/domain-variant/) | **Only** edited in **Subclass** area; per-variant |
| Default complete | Legal aspects **fill required aspect slots** (at capacity for the tree when known) — see DO-ASP-009 and [Destiny Subclass](/prd/destiny-subclass/) DO-SUB-009 |
| [Domain Synergy](/prd/domain-synergy/) | Link kind `aspect` |
| [Area Catalog](/prd/area-catalog/) | Universal pick for aspects (scoped by class/tree when in kit compose) |
| Soft stats | May contribute to full loadout estimate |

### Create / tree-change baseline

After create or tree change: Subclass area is an **empty legal baseline** — **no aspects selected** (BR-BLD-040a).  
User selects aspects (and fragments/abilities) before default is composition-complete.

### Aspect change mid-edit

| Event | Product behavior |
| --- | --- |
| Swap / remove aspect | Recalculate fragment capacity |
| Fragments now over capacity or illegal | **Clear excess / illegal fragments** (prefer auto-trim) so the kit stays savable; show what was cleared if useful |
| New aspect invalid for tree | Not selectable; if tree already changed, wipe path already cleared kit |

Do **not** require Build confirm/fork for aspect-only changes.

## 5. Hard vs soft

### Hard

| Rule | Where |
| --- | --- |
| Aspects must match Build class + tree | Variant Subclass / validation |
| Over max aspect slots cannot save | Variant (DBR-SUB-004) |
| Fragment count > capacity from selected aspects cannot save | Variant |
| Illegal aspect combination cannot save | Variant |
| Default complete needs legal full aspect set (slots filled when capacity known) | Variant §3.2 / DO-SUB-009 |

### Soft

| Topic | Rule |
| --- | --- |
| Synergy aspect coverage | Soft on non-default variants |
| Soft stat contribution from aspects | Display / estimate only |
| Prismatic | Same product rules as other trees (DBR-SUB-002); own aspect pool |

### Object rules

| ID | Rule |
| --- | --- |
| DO-ASP-001 | Aspect is a **child plug** of [Destiny Subclass](/prd/destiny-subclass/); not a standalone compose area. |
| DO-ASP-002 | Edited only in Variant **Subclass** area (DBR-SUB-003). |
| DO-ASP-003 | Must match Build **class + tree**; Prismatic does not widen to all-element aspects. |
| DO-ASP-004 | Presentation is **icon-first**; empty aspect slots visible when unfilled. |
| DO-ASP-005 | **Fragment capacity** is the sum of capacity granted by selected aspects (when known). |
| DO-ASP-006 | Illegal or over-slot aspect sets cannot save; UI disables illegal options when known. |
| DO-ASP-007 | Hashes never primary UI (footer addendum only). |
| DO-ASP-008 | Aspect changes are **variant-local**; no Build confirm/fork. |
| DO-ASP-009 | **Default complete** requires aspect slots filled to the tree’s legal max when that max is known (typically **2**). |
| DO-ASP-010 | When aspect change reduces capacity, **trim or clear** fragments that no longer fit; do not leave a silently illegal kit. Detail: [Destiny Fragment](/prd/destiny-fragment/) DO-FRG-010. |
| DO-ASP-011 | Catalog/search may match hash; result row still shows **name + icon**, not bare hash. |
| DO-ASP-012 | Aspects are **not** build-pinned identity (contrast Super pin / exotic ability pins). |
