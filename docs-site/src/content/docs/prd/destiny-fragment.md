# Fragment — Destiny object

> [!abstract] One-liner
> Modular subclass plug that fills slots granted by selected aspects.

Hub: [Destiny Objects](/prd/destiny-objects/) · Parent: [Destiny Subclass](/prd/destiny-subclass/) · Capacity from: [Destiny Aspect](/prd/destiny-aspect/) · Sibling: [Destiny Ability](/prd/destiny-ability/)

> [!note] DIM reuse

> Visual refs: repo `docs/dim-reference-screenshots/Loadout Optimizer - Subclass Picker Part 1.png`, `Part 2.png`.  
> **Product diverge:** fragments are **per-variant kit** under a **Build-owned tree** — not a DIM vault/loadout product.

## 1. Definition (Destiny / DIM)

A **fragment** is a selectable subclass plug for one **class + element/tree**.

It:

| Role | Meaning |
| --- | --- |
| **Modular effect** | Small permanent bonus, tradeoff, or play-pattern tweak |
| **Slot consumer** | Uses fragment capacity granted by selected [aspects](/prd/destiny-aspect/) |
| **Grid plug** | Appears in a fragment row/grid under aspects in the kit UI |

DIM shows fragments as a dense icon grid under the aspect block, with empty slots for remaining capacity.

### Product placement

| Concern | Owner |
| --- | --- |
| **Tree / element** | [Domain Build](/prd/domain-build/) — shared; fragments must match this tree |
| **Fragment selections** | [Domain Variant](/prd/domain-variant/) — **Subclass** area only; may differ per variant |
| **Capacity budget** | Derived from selected aspects (sum of granted slots) — hard |
| **Pins** | Fragments are **not** build-pinned identity |

Fragments are **not** Build identity. Changing fragments does **not** require confirm/fork.

**Dependency:** Legal fragment count depends on **aspects first**. With zero aspects (empty baseline), capacity is typically **0** — no fragments until aspects grant slots.

## 4. Product use

| Product | How fragments appear |
| --- | --- |
| [Domain Build](/prd/domain-build/) | Not identity; mini kit strip shows selected fragments |
| [Domain Variant](/prd/domain-variant/) | **Only** edited in **Subclass** area; per-variant |
| Default complete | Fragments filled **to capacity** (used == max when capacity known) — DO-SUB-009 |
| [Domain Synergy](/prd/domain-synergy/) | Link kind `fragment` |
| [Area Catalog](/prd/area-catalog/) | Universal pick (scoped by class/tree when in kit compose) |
| Soft stats | Contribute to full loadout estimate when bonuses known |

### Create / tree-change baseline

After create or tree change: **no fragments** (empty legal baseline with aspects/abilities cleared — BR-BLD-040a).

### Aspect change (capacity shrink / grow)

| Event | Product behavior |
| --- | --- |
| Capacity **grows** | More empty slots; user may fill; default incomplete until filled if this is default |
| Capacity **shrinks** | **Auto-trim** excess fragments so used ≤ new max ([Destiny Aspect](/prd/destiny-aspect/) DO-ASP-010) |
| Aspect wipe / tree change | All fragments cleared with kit wipe |

Prefer trim over leaving a silently illegal kit. Optional light notice of what was removed.

### Ordering

Slot **order** of fragments is **not** product-significant for v1 (no ordered power).  
UI may keep stable order for readability; save identity is the **set** of fragment plugs, not permutation — unless implement later finds game order matters (unlikely for fragments).

## 5. Hard vs soft

### Hard

| Rule | Where |
| --- | --- |
| Fragments must match Build class + tree | Variant Subclass / validation |
| Used slots > capacity cannot save | Variant (DBR-SUB-004) |
| Illegal fragment / duplicate when forbidden cannot save | Variant |
| Default complete requires fragments **at capacity** when capacity known | Variant §3.2 / DO-SUB-009 |

### Soft

| Topic | Rule |
| --- | --- |
| Synergy fragment coverage | Soft on non-default variants |
| Soft stat contribution | Display / estimate only |
| Prismatic | Same product rules as other trees (DBR-SUB-002); own fragment pool |
| Under-capacity on non-default | Allowed; only default requires full capacity fill |

### Object rules

| ID | Rule |
| --- | --- |
| DO-FRG-001 | Fragment is a **child plug** of [Destiny Subclass](/prd/destiny-subclass/); capacity comes from [Destiny Aspect](/prd/destiny-aspect/). |
| DO-FRG-002 | Edited only in Variant **Subclass** area (DBR-SUB-003). |
| DO-FRG-003 | Must match Build **class + tree**; Prismatic does not widen to all-element fragments. |
| DO-FRG-004 | Presentation is **icon-first** grid; empty slots and used/max capacity visible. |
| DO-FRG-005 | **Capacity max** = sum of fragment slots granted by selected aspects (when known). |
| DO-FRG-006 | Over-capacity or illegal fragment sets cannot save; UI blocks add when at capacity when known. |
| DO-FRG-007 | Hashes never primary UI (footer addendum only). |
| DO-FRG-008 | Fragment changes are **variant-local**; no Build confirm/fork. |
| DO-FRG-009 | **Default complete** requires fragments filled to capacity (used == max when max known). |
| DO-FRG-010 | When aspect change reduces capacity, **trim excess** fragments (align with DO-ASP-010). |
| DO-FRG-011 | Catalog/search may match hash; result row still shows **name + icon**, not bare hash. |
| DO-FRG-012 | Fragments are **not** build-pinned identity. |
| DO-FRG-013 | With **zero** capacity (e.g. no aspects yet), fragment picks are empty / disabled — not a free unlimited grid. |
| DO-FRG-014 | Same fragment **twice** is illegal when game rules forbid duplicates (default assume no duplicates). |
