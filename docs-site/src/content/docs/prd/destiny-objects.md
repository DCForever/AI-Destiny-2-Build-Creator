# Destiny Objects

**Product definitions for Destiny 2 game entities** this app shows and composes with.

These are **not** app areas (Catalog, Build) and **not** our domain products (Build, Set, Synergy, Variant).  
They are the **shared vocabulary of Destiny data**.

## North Star: DIM (presentation)

| Rule | Meaning |
| --- | --- |
| **Reuse** | Prefer [DIM](https://destinyitemmanager.com/) concepts for **what the object is** and **how it looks** (detail, icons, perk grids, stats, energy, loadout chrome). |
| **DBR-UI-001–005** | DIM is presentation North Star; icon-first; not full DIM product parity. |
| **Diverge** | Our **workflows** (intent, Sets, Synergies, variants) are product-owned — not DIM LO / vault-first. |
| **Refs** | Repo `docs/dim-reference-screenshots/`; bungie-api-ts / manifest definitions in code. |

When DIM and Bungie manifest disagree on labels, prefer **manifest truth** for data and **DIM** for presentation patterns.

## Rules of authoring

1. **STE** — short sentences; fixed terms.  
2. **DIM first for show** — cite presentation pattern; do not invent alternate item chrome without reason.  
3. **Product use second** — how Build Creator attaches, filters, or gates the object.  
4. **No full DIM parity** — vault notes, tags, transfer UI stay non-goals unless specified.  
5. **Stable note titles** — `Destiny Weapon`, not bare `Weapon` (avoids clash with app jargon).  
6. **No bare hashes in primary UI** — plug/item hashes are never row labels or perk titles. Readable name + icon first. Hashes only as an **addendum at the bottom** of a description/detail footer (support/debug). See [Destiny Weapon](/prd/destiny-weapon/) DO-WPN-010–013; apply the same pattern to perks, mods, and other plugs.  
7. **Acquire / farm when data exists** — If Destiny/manifest (or other game data we already load) includes where an item can be obtained, **show it on detail**. Never invent sources. Pattern: [Destiny Weapon](/prd/destiny-weapon/) DO-WPN-030–036; apply to other gear objects as relevant.
